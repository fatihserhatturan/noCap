# noCap Code Quality Standard

This project keeps changes small, explicit, and easy to verify. Every new feature
or refactor must preserve these standards unless the standard itself is updated
first.

## File Size

- Source files must stay at or below 200 lines.
- The limit applies to Python, TypeScript, TSX, CSS, scripts, and tests.
- Excluded files: lock files, generated builds, binary assets, vendored
  dependencies, and package metadata generated by tooling.
- Run `python3 scripts/check_line_limits.py` before finishing work.

## Architecture

- Keep one responsibility per module: pipeline, storage, HTTP, CLI, UI state,
  rendering, styles, and tests should remain separate.
- Prefer small service/facade modules over large orchestration files.
- Public contracts must remain stable unless the change is explicitly scoped:
  CLI commands, HTTP endpoints, FlowMap schema keys, and frontend API payloads.
- Do not duplicate business flow across CLI and web adapters; shared behavior
  belongs in the pipeline layer.

## SOLID Guidelines

- Single responsibility: each module should have one reason to change.
- Open/closed: add new analyzers or metrics as small pluggable units instead of
  editing broad orchestration code.
- Liskov/interface segregation: typed options/results should expose only the
  fields needed by each caller.
- Dependency inversion: UI, CLI, and HTTP layers call service interfaces; they
  should not own analysis logic.

## Text and Localization

- User-facing strings belong in centralized i18n dictionaries.
- Frontend UI strings use `frontend/src/i18n`.
- Python CLI, API progress, and user-facing errors use `nocap/i18n.py`.
- Do not translate schema keys, enum values, CSS class names, endpoint paths,
  test fixtures, or internal identifiers.

## Testing and Verification

Run these before handing off changes:

```bash
python3 -m unittest -q
python3 scripts/check_line_limits.py
cd frontend && npm run typecheck && npm run build
```

- Add focused tests for new analysis behavior.
- Keep tests under the 200-line limit by splitting by topic.
- Preserve existing behavior first; then add new behavior behind clear internal
  interfaces.

## Frontend Standards

- Keep app state in hooks and rendering in focused components.
- Keep Pixi drawing, geometry, hit testing, and lifecycle helpers separate.
- CSS should be split by responsibility and imported in a stable cascade order.
- Do not introduce visible instructional copy unless the product flow requires it.

## Audio Analysis Standards

- Expensive audio features should be computed once and passed through typed
  result objects.
- Store confidence and source metadata for derived signals such as beats,
  onsets, tempo, and sections.
- Prefer deterministic, testable feature extraction helpers over hidden global
  state.
